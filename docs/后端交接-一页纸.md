# Wi-Fi Sense · 给后端的一页纸

> 开场对齐用，一屏读完。细节见同目录《后端交接-接口与状态补充.md》与 `app.py` 里的 `API_CONTRACT`。

## 1. 交付的是什么

单一文件 Streamlit 应用 `app.py`（约 280 KB）+ `assets/` 两张底图 + `.streamlit/config.toml`。

已在容器与内网 K8s 两种环境部署，两处运行同一份代码（仓库 `main`，提交 `14ad8ae`）；内网为热补丁版本 `v0.9.2.1`。具体地址与镜像信息不在本仓库记录，由部署方另行维护。

接口基址通过 `WIFI_SENSE_API_BASE` 注入；留空即走 DEMO 数据源（当前演示模式）。

## 2. 接后端时，前端现在是什么行为

| 能力 | 现状 | 对后端的要求 |
|---|---|---|
| 告警刷新 | 每 30 秒只打 `GET /api/v1/alerts`，局部更新 | 支持 `status` / `room` / `limit`；建议加 `since_id` 或 `updated_after` |
| 告警分页 | 每页 20 条，只在已取的 200 条内翻 | 要翻更早记录，必须给 `offset` 或 `before` |
| 其他数据 | 登录后、切页、点「刷新数据」时全量 `hydrate()` | 首屏要快；`/metrics` 的 `from/to` 用 **UTC 毫秒** |
| 失败 | 保留上一次成功数据 + 一行小字提示 | 统一返回 `{code, message}` 的 JSON，不要返回 HTML 错误页 |
| 鉴权 | 前端 `ws_s` 只用于「刷新不掉线」，不含权限 | 每个接口独立校验身份；401 前端会清 token 并要求重新登录 |

## 3. 需要后端新增或确认的接口

1. `GET /api/v1/alerts?status=&room=&limit=` → 数组，按时间倒序。
2. `GET /api/v1/users/prefs` / `PUT /api/v1/users/prefs` → 界面偏好（主题、密度、动效、卡片细节开关）。没有这个接口，换浏览器后主题会丢，前端已有 `ws_t` 地址栏兜底，可后补。
3. `POST /api/v1/alerts/{id}/ack` → 同步写，成功后前端整页重绘。
4. `GET /health` → 设备 `online` / `last_seen`（判定「离线」「数据陈旧」靠它）。
5. `GET /api/v1/cameras` → `[{id, room, name, status, fps, pose, stream, last_seen}]`，`status` 用「在线 / 离线」，`pose=true` 表示该路上报骨骼关键点，`stream=false` 表示不拉流。
6. `GET /api/v1/poses?frames=30` → `{rooms: {房间名: {camera_id, fps, activity, confidence, frames: [{ts, kp}]}}}`，`kp` 是 COCO-17 的 `[[u,v,score], ...]`，`u/v` 为房间内归一化坐标（0–1）。
   - **只传关键点、不传画面**：姿态估计放在边缘侧（摄像头或网关）完成，前端与接口都不接收图像，这条是隐私要求，不要改成返回截图。
   - 一次返回一小段帧（默认 30 帧 ≈ 2 秒），前端循环播放；不要按帧高频推送，页面刷新与视角保持不了。
7. 空数据请返回 `200 + []`，不要用 5xx 表达"没有记录"。

## 4. 交接时必须一起说清的五个已知限制

1. **HTTP 数据源没有和真实服务联调过**，目前只有契约和 DEMO 实现，首次对接要留联调时间。
2. **分页覆盖范围是最近 200 条**（`WIFI_SENSE_ALERT_LIMIT` 可调），更早的看不到，除非后端支持 `offset`。
3. **告警顶部三张指标卡不参与轮询**，只随整页刷新更新——列表会自动刷、数字会滞后，这是刻意取舍，不是 bug。
4. **登录/权限仍是前端演示账号**，401 过期有处理逻辑但未与真实 token 刷新流程对接。
5. **骨骼是「关键点回放」，不是实时流渲染**：接口给一段帧、前端循环播；真实延迟取决于后端出帧周期。DEMO 里第一路在线、其余离线，用来演示故障态，接真实数据后按 `status` 着色。

## 5. 可调参数（不用改代码）

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `WIFI_SENSE_API_BASE` | 空（DEMO） | 后端基址 |
| `WIFI_SENSE_API_TIMEOUT` | 10 | 单次请求超时（秒） |
| `WIFI_SENSE_API_TTL` | 8 | 非轮询读的进程内缓存（秒）；轮询接口不走缓存 |
| `WIFI_SENSE_ALERT_POLL` | 30 | 告警轮询周期（秒），设 0 关闭 |
| `WIFI_SENSE_ALERT_LIMIT` | 200 | 单次拉取条数上限 |
| `WIFI_SENSE_ALERTS_PAGE_SIZE` | 20 | 告警中心每页条数 |
| `WS_SESSION_SECRET` | 本地默认值 | 前端会话令牌签名密钥，生产必须换 |

## 6. 建议的联调顺序

1. 先通 `GET /health` 与登录态校验（401 路径要能触发）。
2. 再通 `GET /api/v1/alerts`，用 3–5 条数据验证列表、筛选、分页、导出。
3. 然后全量 `hydrate()` 相关接口，看首屏加载时间（目标 < 3 秒）。
4. 最后接 `prefs` 接口，验证"换浏览器主题不丢"。

## 7. 验收标准（可勾选）

- [ ] 未登录访问任一接口返回 401，前端提示「登录已过期」而不是报错白屏。
- [ ] 告警新增后 30 秒内出现在列表，标题「更新于」时间随之变化。
- [ ] 筛选状态/级别/区域后列表正确收敛，清空回到全量。
- [ ] 20 条以上数据能翻页，导出 CSV 为筛选后的全量。
- [ ] 断网或后端 5xx 时列表不清空，只出现一行失败提示。
- [ ] 同一账号在第二个浏览器登录，界面偏好与第一台一致。
