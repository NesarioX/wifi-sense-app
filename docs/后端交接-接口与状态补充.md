# Wi-Fi Sense v0.9.2 · 前端 → 后端交接补充

> 面向后端同学。已有契约见 `app.py` 里的 `API_CONTRACT`（认证、人员、设备、遥测、告警、任务、识别参数、健康检查）。
> 本文只写 **v0.9.2 新增/变化的部分**，以及接口接通后界面会怎么表现，方便一起对齐。

## 1. 版本与改动范围

- 版本：`v0.9.2`（上一版 `v0.9.1` 为纯深色单一主题）。
- 前端重构为四套视觉风格：`glass` 深色玻璃（默认）/ `glass_light` 浅色玻璃 / `dark` 经典深色 / `light` 经典浅色；后两者是原版宽侧栏布局。
- 新增：Apple 风格入场与悬停动效（可在设置页关闭）、登录页「记住我」、设置页四张风格卡整卡可点、风格跨刷新持久化。
- 数据结构、字段语义、接口路径 **全部未变**，`API_CONTRACT` 无需改动。

## 2. 需要新增的接口：用户界面偏好

目前偏好只存在客户端（会话 + 地址栏 `ws_t`），换浏览器就丢。建议加一个正式接口：

```
GET /api/v1/users/prefs
  -> {theme, density, reduce_motion, show_confidence, show_device_detail, auto_brief}

PUT /api/v1/users/prefs
  {theme?, density?, reduce_motion?, show_confidence?, show_device_detail?, auto_brief?}
  -> 204 或返回完整对象
```

字段约束：

| 字段 | 类型 | 取值 | 默认 |
|---|---|---|---|
| `theme` | string | `glass` / `glass_light` / `dark` / `light` | `glass` |
| `density` | string | `标准` / `紧凑` | `标准` |
| `reduce_motion` | bool | 关闭动效 | `false` |
| `show_confidence` | bool | 卡片上显示置信度 | `true` |
| `show_device_detail` | bool | 显示设备型号/固件/RSSI | `true` |
| `auto_brief` | bool | 自动生成今日简报 | `true` |

调用时机建议：登录成功后拉一次（失败就用本地默认，不阻塞进入）；设置页改动后立即 PUT（失败只提示一次，界面保持本地值，不回滚，下次进入再以服务端为准）。非法 `theme` 一律回退 `glass`，不要报错。

## 3. 登录凭证与「记住我」

- 前端已实现：勾选「记住我」→ 令牌有效期 30 天；不勾 → 2 小时。
- 令牌目前是前端 HMAC 签名的 `ws_s`（`WS_SESSION_SECRET` 环境变量），只证明「这个人有过一次成功登录」，**不带任何权限判断**。
- 后端接入后请注意：**所有接口仍必须独立校验身份**，不能把 `ws_s` 当作授权凭据；`ws_s` 只用于刷新页面时不掉线。
- 若后端会话策略与 30 天不一致（例如 token 只发 2 小时），请明确告知，前端会把文案改回实际时长；现在页面写的是「默认 2 小时、勾选记住我后 30 天」。

## 4. 接口接通后界面需要的四种状态

前端已经把错误路径都写好了（`DataSourceError` 会被捕获并展示），以下是需要后端配合的部分：

| 状态 | 触发 | 后端需提供 | 界面表现 |
|---|---|---|---|
| 权限不足 | 家属访问他人房间 | `403` + `{code, message}` | 页面级提示「无权查看该房间数据」，不整页报错 |
| 数据陈旧 | 设备 `last_seen` 超 3 个上报周期（15 分钟） | `GET /health` 的 `devices[].online/last_seen` | 卡片标「离线」、数据区标「数据陈旧」 |
| 部分缺失 | `surface_temp_c` 无来源 | 固定返回 `null`，不要用环境温度填 | 显示「暂无传感器来源」，不画假曲线 |
| 空数据 | 该房间确实没有记录 | `200` + `[]`，**不要用 5xx 表达"没有数据"** | 「目前没有记录」+ 引导操作，而不是报错 |

另：`GET /metrics` 的 `from/to` 请按 **UTC 毫秒**收发，界面只在显示层转 Asia/Shanghai；时间戳不要传本地时间字符串。

## 4.1 告警接口与前端刷新策略（v0.9.2 新增，接后端前必须对齐）

告警区已改成**局部轮询**，不再是"只有点刷新才更新"。这决定了 `/api/v1/alerts` 的调用形态：

| 项 | 约定 |
|---|---|
| 轮询端点 | 只打 `GET /api/v1/alerts`，不打 `/metrics`、不做全量拉取 |
| 轮询周期 | 默认 30 秒；`WIFI_SENSE_ALERT_POLL=0` 可关闭；改周期不需要改代码 |
| 每次条数 | `limit` 默认 200（`WIFI_SENSE_ALERT_LIMIT` 可调），请按此上限返回**最近的 N 条** |
| 支持参数 | `status`（`待处理`/`已确认`）、`room`、`limit`；`level` 由前端过滤，后端可忽略 |
| 分页 | 前端每页 20 条，只在已取到的 200 条内翻页。**如需查看更早记录，请提供 `offset` 或 `before` 参数**，否则前端会明确提示"仅取最近 200 条" |
| 建议增强 | `since_id` 或 `updated_after` 增量参数，避免每 30 秒全表扫描 |
| 失败语义 | 轮询失败时前端**保留上一次成功数据**，在列表下方写一行小字提示，不弹整页错误。请返回结构化错误体，不要返回超长 HTML |

三点提醒：

1. **轮询是可配的，别写死频率**：默认 30 秒 × 每用户一个连接，请评估并发。若后端吃不消，把 `WIFI_SENSE_ALERT_POLL` 调到 60 或 0（关闭），前端不用改代码。
2. **指标卡与列表刷新节奏不同**：列表 30 秒自动更新；顶部"全部/待处理/已确认"三张指标卡跟随整页刷新（切页或点「刷新数据」）。这是有意为之——指标卡不参与轮询，避免每 30 秒重算全量。
3. **确认告警仍是同步写**：`POST /api/v1/alerts/{id}/ack` 成功后前端立刻重绘整页；失败只在该条卡片上报错，不清空列表。

## 5. 部署注意（重要）

- 玻璃态的背景图在 `assets/` 目录（`bg.jpg` 深色底、`bg_light.jpg` 浅色底），代码按 `app.py` 同级 `assets/` 查找。
- **镜像里必须包含 `assets/`**，否则玻璃主题会退回纯色背景（不会崩，但样式不对）。`tools/push_image.py` 已改为把 `assets/` 一起打进 `app/assets/` 层。
- `.streamlit/config.toml` 新增了 `[theme]`（`base = "dark"`、主色 `#F08A4B` 等）。`base` 是全局的，所以**经典浅色风格下个别原生控件仍偏白**——这是已知取舍，不是回归；要彻底解决需要 Streamlit 支持运行时切换 base，或改用自定义组件。

## 6. 遗留项（前端，不由后端负责）

1. 窄屏/手机布局：左侧图标栏 68px 在 390 宽下偏大，需要单独一版移动布局（家属端优先）。
2. 通知推送通道：设置页只有计划项（告警级别、免打扰时段、日报时间），未接任何通道，文案已写明「暂不开放」。
3. 「空间状态」3D 视图写死深色底，浅色玻璃下割裂，需要补浅色配色或统一压成深色展示框。
4. 参考图底部的胶囊导航未实现（顶部胶囊目前是只读面包屑）。
5. 左侧图标按钮的可达名称混入图标字（如 `monitor_heart 实时监测`），需清理。
6. 偏好接口上线后，`ws_t` 地址栏参数可退化为兜底，不必再出现在分享链接里。
